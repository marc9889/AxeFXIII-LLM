Axe-Fx III LLM Controller Windows 10+ · C#/.NET · OpenCode · USB MIDI Purpose: Build a safe, local application that lets an LLM select approved Fractal Axe-Fx III MIDI actions without allowing unrestricted MIDI, SysEx, preset writes, or global configuration changes. Bottom Line. Use OpenCode as a development assistant, not as the live controller. The finished C#/.NET application runs natively on Windows, validates each approved command locally, and sends only known Program Change (PC), Control Change (CC), and wait actions to the Axe-Fx III over USB MIDI. Phase 1 — Install Required Software 2.1 Install Fractal Audio software 1 Install the current Axe-Fx III Windows USB driver. 2 Install Axe-Edit III. 3 Install Fractal-Bot. 4 Connect the Axe-Fx III directly to a USB port on the PC. 5 Avoid USB hubs during initial testing. Back up first. Before changing MIDI settings, use Fractal-Bot to back up system settings and any presets you plan to modify. 2.2 Install .NET SDK Install the .NET 10 SDK. Open PowerShell and verify installation: dotnet --info Confirm that the installed SDK version begins with: 10. 2.3 Install OpenCode Use either the OpenCode Desktop application or the OpenCode CLI. If using the CLI with npm: npm install -g @opencode/cli opencode --version Recommendation. Run the actual C# MIDI bridge natively in Windows PowerShell or Windows Terminal. Do not run the live USB-MIDI bridge inside WSL. 3. Phase 2 — Configure the Axe-Fx III 3.1 Configure incoming MIDI On the Axe-Fx III front panel, open: SETUP → MIDI/Remote Set or verify: MIDI Channel: 1 Receive Program Changes: ON 3.2 Create a test preset Create a low-risk test preset named: AI MIDI TEST Suggested initial chain: Input → Amp → Cab → Delay → Reverb → Output Use low volume. Keep output level conservative while testing MIDI behavior for the first time. 3.3 Configure External Controller 1 In SETUP → MIDI/Remote, configure: External Controller 1 CC: 21 Initial Value: 0 CC 21 is an example. If you choose another unused CC number, use that same number consistently in the Axe-Fx III and in config.json. 3.4 Assign External Controller 1 to Delay Mix 1 Open the test preset in Axe-Edit. 2 Open the Delay block. 3 Find the Mix parameter. 4 Add a modifier/controller. 5 Set the modifier source to External 1. 6 Set a constrained range, for example: Minimum: 8% Maximum: 32% 7 Save the preset. This establishes a safe first continuous MIDI control: MIDI Input Expected Result CC 21, value 0 Low delay mix CC 21, value 64 Medium delay mix CC 21, value 127 High delay mix 4. Phase 4 — Add OpenCode Guardrails Create a file named: AGENTS.md Paste the following content: # Axe-Fx III LLM Controller Project Rules ## Purpose This project is a Windows-native C#/.NET 10 application that controls a Fractal Axe-Fx III through USB MIDI. ## Architecture - OpenCode is a development assistant only. - The compiled C# application is the only component permitted to send MIDI. - An LLM may choose only an approved command ID. - The C# application validates the command ID and sends configured MIDI actions. ## MIDI Safety Requirements - Permit only these MIDI action types: pc, cc, wait. - Allow only MIDI channels 1 through 16. - Allow only Program Change values 0 through 127. - Allow only CC numbers and values 0 through 127. - Reject unknown commands and unsupported action types. - Keep dry-run mode available. - Log every MIDI action before it is sent. ## Explicitly Prohibited - No SysEx support. - No arbitrary raw MIDI messages. - No preset saves, writes, overwrite operations, resets, or firmware actions. - No changes to global I/O, output level, routing, or system settings. - No direct LLM access to MIDI functions. - No automatic execution of live MIDI commands without user approval. ## OpenCode Behavior - Ask before installing packages. - Ask before modifying config.json. - Ask before running dotnet run. - Do not access, display, save, or request API keys. - Prefer small, reviewable changes. - Show a summary of changed files after each task. 5.1 Start OpenCode cd C:\AxeFxLlmController opencode Give OpenCode this first instruction: Read AGENTS.md and treat it as mandatory project guidance. Do not modify any file yet. First summarize: 1. The target architecture. 2. The permitted MIDI action types. 3. The prohibited capabilities. 4. The staged implementation plan. Review before proceeding. If OpenCode proposes unrestricted MIDI, arbitrary parameter editing, SysEx, preset writes, or direct LLM-to-device access, correct it before allowing implementation work. 6. Phase 5 — Build the Deterministic MIDI Bridge Give OpenCode this implementation task: Implement Phase 1 of this project. Create a .NET 10 C# console application that: - Uses NAudio MIDI output. - Lists available Windows MIDI output ports using a /ports command. - Reads a config.json file. - Supports /run for direct execution of approved commands. - Supports --dry-run mode, which prints actions but never opens or sends to a MIDI port. - Supports only pc, cc, and wait action types. - Validates all channels, program values, CC numbers, CC values, and wait durations. - Rejects unknown command IDs and unsupported action types. - Logs every action before sending it. - Does not include any LLM integration yet. - Does not implement SysEx. - Does not run dotnet run. - At the end, summarize all files changed and provide build instructions only. The application should provide these console commands: Command Purpose /ports List available Windows MIDI output ports. /run Run one approved command from the configuration file. /quit Close the application. --dry-run Print actions without sending MIDI. 7. Phase 6 — Create the Command Configuration Create a file named: config.json Use this starter configuration: { "midiPortName": "Axe-Fx III MIDI", "midiChannel": 1, "llm": { "enabled": false, "model": "" }, "commands": { "clean_rhythm": { "description": "Load the clean rhythm sound with low delay.", "requiresConfirmation": false, "messages": [ { "type": "pc", "program": 0 }, { "type": "wait", "milliseconds": 300 }, { "type": "cc", "cc": 21, "value": 20 } ] }, "lead": { "description": "Load the lead sound with medium delay.", "requiresConfirmation": false, "messages": [ { "type": "pc", "program": 1 }, { "type": "wait", "milliseconds": 300 }, { "type": "cc", "cc": 21, "value": 64 } ] }, "ambient_lead": { "description": "Load the lead sound with high delay.", "requiresConfirmation": false, "messages": [ { "type": "pc", "program": 1 }, { "type": "wait", "milliseconds": 300 }, { "type": "cc", "cc": 21, "value": 110 } ] }, "delay_low": { "description": "Set low delay in the current preset.", "requiresConfirmation": false, "messages": [ { "type": "cc", "cc": 21, "value": 20 } ] }, "delay_high": { "description": "Set high delay in the current preset.", "requiresConfirmation": false, "messages": [ { "type": "cc", "cc": 21, "value": 110 } ] } } } Placeholder values. The Program Change values 0 and 1 are examples. Do not assume they select the desired presets on your Axe-Fx III. Test each Program Change and revise the configuration only after verification. 8. Phase 9 — Add LLM Interpretation 10.1 LLM responsibilities The LLM may translate this: Give me a clean rhythm sound. Into this: { "command_id": "clean_rhythm", "reply": "Loading the clean rhythm sound." } The LLM must not generate: { "cc": 21, "value": 95 } 10.2 Add the LLM layer with OpenCode Give OpenCode this task: Implement Phase 2: optional LLM interpretation. Requirements: - Keep all existing direct MIDI behavior unchanged. - Add an LLM interpreter that is disabled by default. - Read the API key only from the OPENAI_API_KEY environment variable. - Never write, log, display, save, or request the API key. - Use the OpenAI Responses API. - Use strict Structured Outputs with JSON Schema. - The output schema must contain only: 1. command_id: one approved command ID from config.json, or null 2. reply: a short plain-language explanation - Do not pass raw MIDI details to the model. - Do not give the model tools, shell access, file access, or MIDI access. - Validate the returned command_id locally against config.json. - If the result is null, invalid, incomplete, refused, or malformed, send no MIDI. - Keep --dry-run behavior fully functional. - Do not run dotnet run. - Show all changed files and explain the failure-handling behavior. 10.3 Store the API key securely In PowerShell: setx OPENAI_API_KEY "your_api_key_here" Protect the key. Do not place the API key in config.json, source code, Git, screenshots, logs, or OpenCode prompts. 10.4 Enable LLM mode After reviewing and building the implementation, update: "llm": { "enabled": true, "model": "gpt-4.1" } Use a model available to your account that supports strict structured output. The exact model name can be changed later without changing the MIDI control design. 10.5 Test the LLM in dry-run mode dotnet run -- --dry-run Test clear requests: Give me a clean rhythm sound. I need a huge ambient lead sound. Test unclear or prohibited requests: Make it warmer and more modern. Overwrite my lead preset and change the amp model. Expected result. Clear requests resolve to an approved command ID. Unclear, unsupported, malformed, or prohibited requests resolve to null and send no MIDI. 11. Final Operating Principle Keep the LLM expressive, but keep the MIDI bridge deterministic. The LLM may understand phrases such as “ambient lead,” “clean rhythm,” or “more delay.” The local C# application decides whether that phrase maps to a preapproved action and sends only the known MIDI sequence stored in the configuration file.
